C-Star now refuses, before anything is built or queued, a tiling that ucla-roms stops on when it interpolates surface forcing from the coarse grid: ``init_coarse`` (ucla-roms 0.6.2 and later) gives each tile ``ceil((llm // 2) / np_xi)`` coarse points (likewise ``mmm``, ``np_eta``) and stops with "tiling too fine for coarse-resolution forcing inputs" when that is 2 or fewer.
- Forge's early refusal (``check_tile_sizes``, ``cstar blueprint check``) applies it, before any input is generated, to the tiles and coarse-grid flags generation will write (``domain.partitioning``, and ``interp_frc`` as an explicit ``coarse_grid_mode`` sets it), so a saved blueprint is judged on the values it will run with; and the composed namelist (rule L in ``cstar.roms.precheck``) when the staged ``cppdefs.opt`` shows a forcing module whose switch is on: ``interp_bulk_frc`` with ``BULK_FRC``, ``interp_flux_frc`` without it, ``interp_bgc_frc`` with MARBL or BEC2. Auto-tiling is not checked, since ROMS picks the tiles then.
